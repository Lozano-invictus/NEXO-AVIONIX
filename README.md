# Project Timeline

The project is being developed through an iterative sprint-based methodology, which allows for a gradual and organized transition from conceptual design to functional implementation. This approach has made it possible to validate each stage of the system progressively, while preserving coherence between the visual design, the logical structure, and the technical development of the platform.

---

## Sprint 1: Visual Design, Initial Prototyping, and Frontend Development

**Approximate duration:** 1 month  
**Start:** End of February 2026  
**End:** March 26, 2026  

This sprint focused on the initial definition of the system in both visual and structural terms. The main objective was to establish a clear interface proposal, validate the user experience, and create the first functional foundation of the application. During this phase, the project underwent several iterations in Figma due to adjustments in usability, layout, and visual identity. These revisions allowed the design to evolve toward a more consistent and professional interface.

In parallel, the development process began with the initialization of the codebase and the organization of the project structure. The frontend was implemented using HTML, CSS, and JavaScript, based on the approved prototypes. The work also included the creation of the GitHub repository for version control, the definition of the navigation flow through a UML-based model, and the development of the main modules of the platform.

### Main activities carried out in this sprint included:

- Initial development of the application prototype in Figma.
- Creation of the GitHub repository to begin version control.
- Development of the UML navigation model to represent user interaction flows.
- Iterative redesign of the client mockup, including two to three interface improvements.
- Definition of the main modules of the system, such as login, registration, client area, super administrator, and airline agent.
- Visual validation of the consistency between screens and navigation flow.
- Refinement of the color palette and the overall interface composition.
- Start of frontend coding on March 26, 2026.
- Project structuring using HTML, CSS, and JavaScript.
- Implementation of the first main views.
- Internal navigation integration between modules.
- First commits in GitHub during the last week of March.
- Last recorded commit on April 4, 2026.
- Current state of the sprint: the system is functionally advanced at a visual level and operates with simulated data.

---

## Sprint 2: Database Design and Implementation

**Approximate duration:** April 8, 2026 – May 23, 2026  
**Start:** April 8, 2026  
**End:** May 23, 2026  

This sprint focused on the design, structuring, implementation, and validation of the system’s database. The main objective of this phase was to establish the logical and relational foundation required for the operational functionality of the platform, ensuring proper organization, integrity, scalability, and consistency of the information managed by the system.

During this sprint, the database architecture was developed based on the functional requirements identified in the previous phase. The Entity–Relationship (E-R) model and the relational model were defined to represent the interaction between the different modules and entities of the platform. The implementation process included the creation of tables, definition of relationships, validation of constraints, and preparation of the database structure for future integration with the application logic.

### Main activities carried out in this sprint included:

- Design of the Entity–Relationship (E-R) model.
- Development of the relational database model.
- Identification and definition of entities and attributes.
- Establishment of primary keys and foreign keys.
- Definition of relationships between modules and tables.
- Structuring of operational records related to clients, flights, reservations, tickets, destinations, and tourist packages.
- Organization and normalization of data to improve consistency and reduce redundancy.
- Preparation of the database for future backend integration.
- Validation of logical consistency between the visual system design and the data structure.
- Documentation of the database architecture and relational structure.

This sprint represented a significant milestone in the project, as it established the technical infrastructure necessary for the transition from a visual prototype to a more functional and scalable software solution.
